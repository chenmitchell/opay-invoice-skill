## 二、怎麼遮才算遮乾淨

### ✅ 正確做法

- **實心不透明矩形**塗黑（建議純黑 `#000000` 或深色 `#1F2937`）。
- 或**先改資料再截圖**——這是最安全的做法：在測試環境用假資料操作，直接截乾淨的圖。
- 或**重新繪製示意圖**（Mermaid、Figma），完全避開真實畫面。

### ❌ 錯誤做法

| 做法 | 為什麼不行 |
|---|---|
| 馬賽克／像素化 | **可被還原**，尤其是數字與短字串 |
| 高斯模糊 | 同上，模糊半徑小的時候幾乎可完全復原 |
| 半透明色塊 | 調整對比就看得到 |
| 只縮小圖片 | 原始資料仍在檔案中（有些格式會保留） |
| 在 HTML 用 CSS 遮蔽後截圖 | 若截的是網頁而非圖片，原始 DOM 仍在 |
| 用截圖工具的「標註」功能但沒有壓平圖層 | PNG/PSD 可能保留圖層 |

### 別忘了 metadata

```bash
# 檢查 EXIF / metadata（可能含 GPS、裝置名稱、軟體版本）
exiftool screenshot.png

# 清除所有 metadata
exiftool -all= screenshot.png

# 或用 ImageMagick 重新輸出（同時壓平圖層）
convert screenshot.png -strip screenshot-clean.png
```

## 三、檔案規範

| 項目 | 規範 |
|---|---|
| **格式** | UI 截圖用 `.png`；照片用 `.jpg`；流程與架構圖**優先用 Mermaid 寫在 Markdown 裡**，不要存成圖片 |
| **命名** | 全小寫、連字號分隔、語意清楚：`vendor-stage-login.png`、`b2c-issue-success.png` |
| **尺寸** | 寬度建議 1200–1600px；超過 2000px 請壓縮 |
| **檔案大小** | 單檔 **≤ 500 KB**（PNG 請跑過 `pngquant` 或 `oxipng`） |
| **深色／淺色** | 若截的是本 repo 的工具（測試主控台），請截**深色主題**版本以符合視覺一致性 |
| **語言** | 介面請用**繁體中文**版本 |

```bash
# 壓縮建議
pngquant --quality=65-85 --output out.png -- in.png
oxipng -o 4 --strip safe out.png
```

## 四、每張圖都要有替代文字

在 Markdown 中引用時，**替代文字必須描述圖的內容**，不能只寫「截圖」。

```markdown
<!-- ❌ 不好 -->
![截圖](docs/images/b2c-issue-success.png)

<!-- ✅ 好 -->
![測試主控台第二關「唯讀 API 實測」的執行結果，四支 API 全數顯示綠底白字的「✅ 通過」，並列出各自的回應時間](docs/images/console-readonly-pass.png)
```

替代文字的要求（依 [`docs/accessibility.md`](../accessibility.md)）：

- 描述**圖裡發生了什麼**，不是「這是一張圖」。
- 若圖中有關鍵數值或錯誤訊息，**在替代文字或圖說中重複一次**。
- 不要在替代文字中重複已經寫在內文的資訊（避免螢幕閱讀器重複朗讀）。
- 純裝飾性圖片用空替代文字 `![]()`。

## 六、貢獻截圖的檢查清單

提交含截圖的 PR 前，逐項確認：

```text
[ ] 發票號碼、隨機碼已改成 AA00000000 / 0000
[ ] 統一編號已改成 00000000
[ ] 買受人 Email、手機、姓名、地址全部替換或塗黑
[ ] 正式環境 MerchantID 已替換
[ ] HashKey / HashIV 整段塗黑（不是打碼、不是模糊）
[ ] 後台帳號密碼、token、cookie 已塗黑
[ ] 內部系統網址、內網 IP、公司 logo 已處理
[ ] 瀏覽器分頁、書籤列、桌面通知已裁切
[ ] 作業系統使用者名稱已塗黑
[ ] 遮蔽用的是實心矩形，不是馬賽克或模糊
[ ] 圖層已壓平（沒有可還原的圖層）
[ ] metadata 已清除（exiftool -all=）
[ ] 檔案 ≤ 500 KB
[ ] 檔名符合命名規範
[ ] Markdown 引用處有描述性的替代文字
[ ] 自己用放大鏡看過一遍，確認沒有漏網之魚
```

> 不確定某項資訊算不算敏感？**當作敏感處理。** 遮多了頂多圖比較醜，遮少了是個資事件。

## 七、關於「圖 vs Mermaid」

**能用 Mermaid 畫的，就不要用截圖。**

| | Mermaid | 截圖 |
|---|---|---|
| 可搜尋 | ✅ 文字可 Ctrl+F | ❌ |
| AI 可讀 | ✅ | ⚠️ 需 OCR |
| 可修改 | ✅ 改文字即可 | ❌ 要重截 |
| 版本控制 diff | ✅ 看得出改了什麼 | ❌ 二進位 |
| 無障礙 | ✅ 可附純文字重述 | ⚠️ 只能靠 alt |
| 脫敏風險 | ✅ 無 | ❌ 高 |
| 檔案大小 | ✅ 幾 KB | ❌ 幾百 KB |

**截圖只適合用在**：真實 UI 的操作位置指引（「這個按鈕在右上角」）、官方後台的畫面說明。
**流程、架構、狀態機一律用 Mermaid**，規範見 [`docs/accessibility.md`](../accessibility.md)。
