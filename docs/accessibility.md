# 視覺與無障礙規範（accessibility.md）

> 本檔是 **opay-invoice-skill 全 repo 的視覺契約**。
> README、`references/`、`guides/`、`templates/` 裡所有 Mermaid 圖與所有 HTML 介面，都在圖後標註「配色遵循 `docs/accessibility.md`」——指的就是這一份。
> 本專案為**非官方的個人專案**，本規範是本 repo 的自我要求，不代表任何官方標準或法規符合性聲明。

---

## 0. 一句話總結

**深底、白字、直角線、圖示＋文字雙編碼、每張圖都附純文字重述。**
只用九個核可底色，全部對白字的對比 ≥ 7:1（WCAG AAA）。

---

## 1. 為什麼要有這份規範

電子發票的整合文件有三個先天不利條件：

1. **圖多**：狀態機、時序、流程分支很難只用文字講清楚。
2. **讀者環境雜**：GitHub 深色／淺色主題、手機、投影機、印表機、螢幕閱讀器、AI 爬蟲，全都會讀到同一份 Markdown。
3. **讀者常在壓力下閱讀**：多半是發票開不出來、當天要上線的時候才翻文件。

所以本 repo 不追求好看，追求「**在最壞的顯示條件下仍然讀得懂**」。
深底白字在 GitHub 深色與淺色主題下都成立；直角連線在低解析投影時不會糊成一團；圖示＋文字雙編碼讓色盲讀者與純文字爬蟲拿到一樣的資訊。

## 2. 核可色盤（唯一合法的九個 `fill:`）

任何 Mermaid 圖的 `fill:` **只能**是下列九色之一。文字一律 `#FFFFFF`，外框一律 `stroke:#FFFFFF,stroke-width:3px`。

| 用途 | 色碼 | 對 `#FFFFFF` 對比 | WCAG | 典型語意 |
|---|---|---|---|---|
| 主要／起點 | `#1E3A8A` | **10.36:1** | AAA | 商店系統、使用者輸入、流程起點 |
| 次要／處理 | `#3730A3` | **9.93:1** | AAA | 後端服務、轉換與組裝步驟 |
| 加密／安全 | `#581C87` | **10.88:1** | AAA | AES 加解密、金鑰、簽章 |
| 外部服務 | `#164E63` | **9.11:1** | AAA | 歐付寶加值中心、對外 API 呼叫 |
| 資料／儲存 | `#134E4A` | **9.48:1** | AAA | 資料庫、佇列、稽核 log |
| 警示／人工 | `#78350F` | **9.07:1** | AAA | 需人工介入、待確認、逾時觀察 |
| 中性／說明 | `#1F2937` | **14.68:1** | AAA | 註解節點、群組標題、備註 |
| **成功** | `#14532D` | **9.11:1** | AAA | 成功終點、`RtnCode=1` |
| **失敗** | `#7F1D1D` | **10.02:1** | AAA | 失敗終點、錯誤分支 |

> 對比值以 WCAG 2.x 相對亮度公式計算（白字 vs 該底色）。WCAG AAA 對一般文字的門檻是 7:1，九色全數通過。
> **禁止**：淺色底（黃、淺藍、淺綠）、黑字、`stroke-width` 小於 3px、未指定 `color:` 而讓 Mermaid 自行決定文字色。

### 為什麼是這九色

- 取自 **Okabe-Ito 色盲安全色盤**的色相分群（藍／靛／紫／青／藍綠／橙褐／灰／綠／紅），彼此在紅綠色盲（deuteranopia / protanopia）與藍黃色盲（tritanopia）下仍可分辨色相或明度。
- 每色都壓到 L\* 很低的深色，確保白字對比 ≥ 7:1，也確保在 GitHub **淺色主題**下不會與白色畫布融在一起、在**深色主題**下不會刺眼。
- 成功／失敗刻意選同明度的綠與紅（9.11 vs 10.02），**因此不可只靠顏色區分**——必須同時附圖示（✅／❌）與文字。

## 3. Mermaid 圖規範

### 3.1 必附的 init 標頭（逐字複製）

每張 Mermaid 圖的第一行都要是：

```
%%{init: {'flowchart': {'curve':'step','htmlLabels':true,'useMaxWidth':true},'themeVariables': {'fontSize':'16px','fontFamily':'ui-sans-serif, system-ui, sans-serif'}}}%%
```

| 設定 | 值 | 理由 |
|---|---|---|
| `curve` | `step` | **直角連線**。貝茲曲線在節點密集時會互相穿越，直角線的走向在低解析度下仍可追蹤。 |
| `htmlLabels` | `true` | 允許 `<br/>` 換行，讓「中文＋英文」雙行標籤不會擠成一行。 |
| `useMaxWidth` | `true` | 圖隨容器縮放，手機上不會橫向捲動到看不見。 |
| `fontSize` | `16px` | **最小字級 16px**。低於此值在手機與投影機上不可讀。 |
| `fontFamily` | `ui-sans-serif, system-ui, sans-serif` | 交給系統挑選在地字型，避免中文 fallback 成襯線字或方框。 |

### 3.2 節點標籤：圖示 ＋ 中文 ＋ 英文

```
A["🧾 開立發票<br/>Issue Invoice"]
```

三重編碼的理由：

- **圖示**：色盲或單色列印時仍可辨識語意類別。
- **中文**：本 repo 的主要讀者是台灣開發者。
- **英文**：給 AI 助手、國際協作者、以及螢幕閱讀器在中文語音包缺失時的備援。

常用圖示對照（建議沿用，維持全 repo 一致）：

| 圖示 | 語意 | 圖示 | 語意 |
|---|---|---|---|
| 🧾 | 開立發票 | 🔐 | 加密 |
| 🏪 | 商店系統 | 🔓 | 解密 |
| 🖥️ | 後端服務 | 📮 | 上傳財政部 |
| 🏢 | 歐付寶加值中心 | 🔢 | 字軌／號碼 |
| 🏛️ | 財政部 | ✅ | 成功 |
| 📱 | 載具／手機條碼 | ❌ | 失敗 |
| 💸 | 折讓 | ⚠️ | 警示／需人工 |
| 🚫 | 作廢 | 🔁 | 重試／輪詢 |
| 🔍 | 查詢 | ⏱️ | 逾時／期限 |

### 3.3 每張圖前後的兩行標註（缺一不可）

**圖前一行**——純文字重述，給螢幕閱讀器、純文字爬蟲、以及 Mermaid 渲染失敗時的讀者：

```
> 🧭 **純文字重述（螢幕閱讀器友善）**：（用完整句子把圖的節點與流向講一遍，不要寫「如上圖」。）
```

**圖後一行**——配色聲明，指回本檔：

```
> ♿ 配色遵循 [`docs/accessibility.md`](docs/accessibility.md)：WCAG AAA 對比 ≥7:1、Okabe-Ito 色盲安全色盤、16px 字體、直角連線、圖示＋文字雙編碼。
```

（在 `guides/`、`references/` 等子目錄中，連結請改成相對路徑 `../docs/accessibility.md`。）

純文字重述的寫法要求：

- 用**完整句子**，不是節點名稱的清單。
- 講清楚**分支條件**（「若 `RtnCode` 等於 1 則進入成功分支，否則進入錯誤處理」）。
- 講清楚**方向**（誰呼叫誰、資料往哪流）。
- 不得只寫「這是一張流程圖」。

## 4. HTML／前端介面規範

適用於 `templates/opay-test-console/console.html` 以及任何本 repo 產出的網頁。

| 項目 | 要求 |
|---|---|
| 對比 | 一般文字 ≥ 7:1（AAA）、大字（≥18.66px 粗體或 ≥24px）≥ 4.5:1 |
| 觸控目標 | **≥ 44 × 44 px**（本 repo 實作取 48px，留一點餘裕） |
| focus ring | 鍵盤 focus 時必須有**可見的白色外框**（`outline: 3px solid #FFFFFF; outline-offset: 2px`），**嚴禁** `outline: none` |
| 鍵盤操作 | 所有互動元件可用 Tab 抵達、Enter／Space 觸發，順序符合視覺順序 |
| 表單 label | 每個 `<input>` / `<select>` / `<textarea>` 都要有對應的 `<label for="...">`，不可只靠 `placeholder` |
| 錯誤訊息 | 與欄位以 `aria-describedby` 關聯，且訊息本身要說「怎麼修」而不只是「錯了」 |
| 狀態播報 | 非同步結果（API 回應、驗證通過／失敗）放進 `aria-live="polite"` 區塊；破壞性操作的確認用 `aria-live="assertive"` |
| 狀態編碼 | **顏色＋圖示＋文字**三重，例如 `✅ 通過`（綠底）／`❌ 失敗`（紅底），不可只有色塊 |
| 動畫 | 尊重 `prefers-reduced-motion: reduce`，關閉非必要動畫 |
| 縮放 | 支援瀏覽器縮放至 200% 不破版；不得使用 `user-scalable=no` |
| 語言 | `<html lang="zh-Hant">` |

## 5. 文件（Markdown）規範

- **標題階層不可跳號**（`##` 之後不可直接出現 `####`），螢幕閱讀器靠標題導覽。
- **表格必須有表頭列**，且第一欄是可辨識的鍵（Endpoint 名、欄位名），不要用純數字當唯一識別。
- **連結文字要能單獨讀懂**：寫 [`references/encryption-aes.md`](../references/encryption-aes.md)，不要寫「點這裡」。
- **程式碼區塊要標語言**（```` ```python ````、```` ```bash ````），語法高亮同時也是給 AI 的型別提示。
- **emoji 不承載唯一語意**：`⚠️ 警告：…` 可以，只放一個 `⚠️` 不加文字不行。
- **不使用純色差表達的表格儲存格**（GitHub Markdown 本來也不支援，此處是明文禁止避免有人用 HTML 繞過）。

## 6. 自我檢查

提交前至少跑過這三項：

```bash
# 1. 色盤檢查：所有 Mermaid fill: 是否都在核可色盤內
grep -rhno 'fill:#[0-9A-Fa-f]\{6\}' --include='*.md' . \
  | grep -v -E 'fill:#(1E3A8A|3730A3|581C87|164E63|134E4A|78350F|1F2937|14532D|7F1D1D)' \
  && echo '❌ 有未核可色' || echo '✅ 色盤全數合規'

# 2. 每張 Mermaid 圖是否都有 init 標頭
grep -rc '```mermaid' --include='*.md' .
grep -rc "%%{init:" --include='*.md' .   # 兩個數字必須相等

# 3. 內部連結是否都指向存在的檔案（見 scripts/ 內的連結檢查腳本）
```

人工檢查項目：

- [ ] 每張圖前有 `🧭 純文字重述`，且重述本身讀得懂（把圖遮住只讀文字，仍知道流程）
- [ ] 每張圖後有 `♿ 配色遵循` 標註
- [ ] 節點標籤是「圖示＋中文＋英文」
- [ ] 成功／失敗不只靠綠紅，還有 ✅／❌
- [ ] 用瀏覽器 Ctrl+F 找得到圖裡的關鍵字（代表文字不是圖片）
