# 08 · B2C 發送通知與發票列印

`InvoiceNotify` 補發 Email／SMS 通知，`InvoicePrint` 取得可列印的發票內容；含超商 KIOSK 事務機的參數帶法。

> **對應 API**：[`InvoiceNotify`](../references/b2c-api-reference.md#19-發送發票通知--invoicenotify)、[`InvoicePrint`](../references/b2c-api-reference.md#20-發票列印--invoiceprint)
> **前置條件**：發票已開立；如需自行列印或 KIOSK 列印，**須先向歐付寶業務申請開通**（見 [`02-preflight-checklist.md`](02-preflight-checklist.md) §2.2）。

---

## 1. 先確認你需不需要串 `InvoiceNotify`

官方原文（i100 §18）：

> 若不撰寫此 API，則可透過**廠商後台功能**處理；若廠商後台 > 發票通知方式設定通知選項有開啟，**除非有額外補送通知需求，否則不須再串接此 API，以免重複通知**。

| 情況 | 該不該串 |
|---|---|
| 只要開立時自動通知消費者 | ❌ 不用。到廠商後台開通知開關就好（或用 [`10-b2c-notify-settings.md`](10-b2c-notify-settings.md) 的 API 設定） |
| 客服要「重寄一次發票通知」 | ✅ 要串 |
| 要寄到與開立時不同的信箱 | ✅ 要串 |
| 中獎通知要另外處理 | ✅ 要串（`InvoiceTag=AW`） |

> **為什麼要先問「需不需要」**：後台開關 + 這支 API 兩邊都開，消費者會收到**兩封信**。重複通知是很典型的客訴來源，而且事後很難查是哪一邊送的。

## 2. `InvoiceNotify` 參數

```python
c.invoice_notify(
    invoice_no="AA12345678",
    notify="E",          # S 簡訊 / E 電子郵件 / A 皆通知
    invoice_tag="I",     # I 開立 / II 作廢 / A 折讓開立 / AI 折讓作廢 / AW 中獎
    notified="C",        # C 客戶 / M 特店 / A 皆發送
    NotifyMail="buyer@example.com",
)
```

| 參數 | 值 | 規則 |
|---|---|---|
| `Notify` | `S` 簡訊／`E` Email／`A` 皆通知 | — |
| `InvoiceTag` | `I` 開立／`II` 作廢／`A` 折讓開立／`AI` 折讓作廢／`AW` 中獎 | **`A` 或 `AI` 時 `AllowanceNo` 必填**，否則查無資料 |
| `Notified` | `C` 客戶／`M` 特店／`A` 皆發送 | `A` 時「請注意廠商後台設定是否接受通知」 |
| `Phone` / `NotifyMail` | 二擇一 | **`NotifyMail` 未填時 `Phone` 必須有值；反之亦然**。多組 Email 用**半形分號**分隔 |

> ⚠️ **B2C 的 `InvoiceTag` 是字母（`I`/`II`/`A`/`AI`/`AW`），B2B 的是數字（`1`–`10`）**，欄位名相同。跨系統時不要共用同一組常數，見 [`enums.md` §10.4](../references/enums.md#104-️-invoicetag--b2c-字母-vs-b2b-數字)。

### 2.1 測試環境不會主動發信

官方原文：

> ※注意事項 (1)：**測試環境下歐付寶不會『主動』發送任何通知**，需於廠商管理後臺使用『補發通知』，才會寄送通知信到指定信箱。

> **為什麼要知道這件事**：在測試環境驗證「消費者有沒有收到信」是**驗不出來的**。你只能驗 API 回應與參數規則。把「收信驗證」排進正式環境的上線檢查，不要以為測試通過就等於會寄。
>
> ⚠️ 同時：**測試環境請勿帶入真實電子信箱**，避免個資外洩。

### 2.2 中獎通知的時點

官方原文：「歐付寶系統會於**奇數月份的 29 號**核對中獎發票，廠商需先設定通知方式以便通知消費者。」

**實務**：中獎通知是**每兩個月一次的批次事件**。如果你的客服流程沒有預期到這個時間點，會在 29 號突然湧入一批「我中獎了要怎麼領」的詢問。把它排進客服行事曆。

## 3. `InvoicePrint` 發票列印

```python
res = c.invoice_print(
    invoice_no="AA12345678",     # 2 碼字軌 + 8 碼數字
    invoice_date="2026-08-18",   # yyyy-MM-dd 或 yyyy/MM/dd
    PrintStyle=1,                # 1 單面(預設) / 2 雙面 / 3 熱感應紙
)
```

| `PrintStyle` | 意義 |
|:---:|---|
| `1` | 一般列印（單面）— **預設** |
| `2` | 一般列印（雙面） |
| `3` | 熱感應紙列印 |

> ⚠️ **自行列印電子發票需要「密碼種子」**（i100 §1 / i301 §3 原文：「特店若有自行列印電子發票之需求需**申請密碼種子**，請聯繫業務人員辦理」）。沒申請的話，`GetIssue` 不會回傳 `QRCode_Left` / `QRCode_Right` 的壓碼內容，你印出來的發票 QR Code 是無效的。

## 4. 超商 KIOSK 事務機列印

**除須向業務申請開通外**，參數必須按下表帶（i100 §7 原文）：

| 情境 | `Print` | `CarrierType` | `CustomerIdentifier` | `Donation` | 限制 |
|---|:---:|:---:|:---:|:---:|---|
| 列印**消費發票**（ibon） | `1` | `""` | `""` | `0` | **只能列印一次**，之後中獎也無法再次列印 |
| 列印**中獎發票**（ibon、FamiPort） | `0` | `1` | `""` | `0` | **只能列印一次** |
| 折讓後發票金額為 **0 元** | — | — | — | — | **不可列印** |

> 🚨 **「只能列印一次」是不可逆的。** 消費者在 ibon 印了消費發票之後，就算後來中獎也**無法再印中獎發票**。如果你的商品有中獎領獎需求（例如高單價商品），要在 UI 上明確告知消費者這個取捨，不要讓他在不知情的情況下按下去。
>
> **為什麼會踩到**：這兩組參數組合看起來只差在 `Print` 和 `CarrierType`，很容易被當成「兩種都支援」。實際上它們是互斥的**一次性選擇**。

## 5. 通知失敗怎麼辦

`InvoiceNotify` 是**唯一一支「重送很安全」的通知類 API**——重複發送最多只是消費者收到兩封信，不會產生財務後果。

| 情況 | 建議 |
|---|---|
| `RtnCode != 1` | 可重試（指數退避），並記錄 `RtnCode` / `RtnMsg` 原文 |
| 消費者說沒收到 | 先確認廠商後台的通知開關是否開啟；再用本 API 補發 |
| Email 退信 | 這支 API 不會告訴你退信。要靠自己的寄信紀錄或客服流程 |

⚠️ 但**不要**把它放進「自動重送直到成功」的無限迴圈。消費者收到 20 封發票通知信，是比沒收到更嚴重的客訴。

---

### 常見錯誤

1. **後台通知開關與 `InvoiceNotify` 兩邊都開。** 消費者收到兩封信。先確認後台設定，再決定要不要串這支 API。
2. **`InvoiceTag` 用 `A`/`AI` 卻沒帶 `AllowanceNo`。** 官方明寫「否則會**查無資料**」。
3. **`Phone` 與 `NotifyMail` 兩個都留空。** 兩者至少要有一個有值，不是「都不填就用預設」。
4. **在測試環境驗「有沒有收到信」。** 測試環境**不會主動發送任何通知**，只驗規則。
5. **沒申請密碼種子就自行列印。** QR Code 壓不出來，印出的發票無效。
6. **KIOSK 消費發票與中獎發票的參數搞混。** 只能列印一次，選錯就沒有第二次機會。
