# /opay-allowance —— 開立折讓

折讓是「這張發票的金額要往下修」，用在**退了一部分**或**事後折價**。
它不消耗發票號碼，比作廢重開便宜得多 —— 但**一樣不可逆**。

## 步驟 1：先確認折讓真的是他要的

| 使用者的狀況 | 該做的事 |
|---|---|
| 退了其中一項商品／退了部分金額 | ✅ 折讓 |
| 整筆交易取消 | 作廢（`/opay-void`） |
| 買受人或品項打錯，交易仍成立 | 註銷重開（`/opay-void`） |
| 已經開了折讓但開錯 | 作廢折讓（`AllowanceInvalid`） |

## 步驟 2：確認要用哪一支

| 情境 | API | 文件 |
|---|---|---|
| B2C 一般折讓（紙本開立，賣方直接開） | `Allowance` | i100 §8 |
| B2C 線上折讓（通知買方，買方線上同意） | `AllowanceByCollegiate` | i100 §8 |
| B2C 作廢折讓 | `AllowanceInvalid` | i100 §10 |
| B2C 取消線上折讓（買方還沒同意前撤回） | `AllowanceInvalidByCollegiate` | i100 §11 |
| B2B 折讓（兩段式） | `Allowance` → `AllowanceConfirm` | i200 §13–14 |
| B2B 作廢折讓（兩段式） | `CancelAllowance` → `CancelAllowanceConfirm` | i200 §15–16 |

**一般折讓 vs 線上折讓的差別**：
一般折讓是賣方單方面開立（對應紙本折讓單，賣方要留存買方簽收證明）；
線上折讓是系統通知買方、由買方在線上按同意。
**買方是公司行號時通常要走線上折讓**，不確定就問使用者他們公司的作業慣例。

## 步驟 3：先查原發票，確認折讓額度

用 `GetIssue` 撈原發票，再用 `GetAllowanceList` 撈已開過的折讓。

**折讓總額不得超過原發票金額。** 這件事一定要在送出前自己算過：

```
原發票：      AA12345678，總額 NT$ 1,050
已折讓：      NT$ 200（1 筆）
本次折讓：    NT$ 300
累計折讓：    NT$ 500  ≤  NT$ 1,050  ✅
```

超過就停下來，不要送出。

## 步驟 4：收集必填欄位

- `InvoiceNo` + `InvoiceDate`：原發票號碼與日期
- `AllowanceNotify`：通知方式（簡訊／email／皆不通知）
- `CustomerName` / `NotifyMail` / `NotifyPhone`：通知對象
- `AllowanceAmount`：折讓總額（**必須等於明細加總**）
- `Items[]`：折讓明細，每筆要 `ItemName`、`ItemCount`、`ItemWord`、`ItemPrice`、`ItemTaxType`、`ItemAmount`

明細的課稅別要跟**原發票對應品項**一致，混合稅率的發票特別容易在這裡出錯。

## 步驟 5：二次確認（不可省略）

```
確認一下：

  操作：      開立折讓（一般開立 / 線上開立）
  原發票：    AA12345678（2026-08-18，總額 NT$ 1,050）
  已折讓：    NT$ 200
  本次折讓：  NT$ 300
  折讓後餘額：NT$ 550
  環境：      正式環境 ⚠️
  可逆性：    不可逆（開錯只能再開一張「作廢折讓」）

確定要執行請完整回覆：
「確認折讓 AA12345678 金額 300」
```

**回覆必須同時包含發票號碼與金額**才算數。

## 步驟 6：執行與記錄

- `RtnCode = 1` 才算成功，並記下 `AllowanceNo`（折讓單號，之後要作廢折讓會用到）。
- 寫入稽核紀錄：誰、何時、對哪張發票折讓多少、原因。
- **失敗不要重試**，先用 `GetAllowanceList` 查是不是其實已經開成功了。

## 你**不可以**做的事

- ❌ 不可以在沒有先查原發票的情況下開折讓。
- ❌ 不可以讓累計折讓超過原發票金額。
- ❌ 不可以在使用者沒有逐字確認前執行。
